# Auto Meet — бета (Electron)

Нова версія програми з графічним інтерфейсом і **без консолі**. Основна Python-версія
(`auto_meet.py` у корені репозиторію, автооновлення з `main`) **не змінюється й працює як раніше**.

## Що в бета-версії
- Одне вікно: таймер, наступна пара, скільки пар лишилось, журнал подій.
- Вибір групи: спочатку курс, потім група; пошук у довгих списках.
- Кнопка **«Заміняю пару»** для викладача: група → пара → курс Classroom.
- Налаштування у вікні: автозапуск, повторна прив'язка курсів, оновлення розкладу, журнал, скидання.
- Іконка в треї; програма працює у фоні, поки не натиснете «Вийти».
- Не дає комп'ютеру заснути, поки працює (замість `caffeinate`).
- Розклад бере з того ж `schedule.json` у `main` (оновлюється сам, як і в основній версії).

## Як вона співіснує з основною версією
- Окрема папка даних (`AutoMeet Beta` у профілі користувача), окремий профіль браузера, окремий автозапуск.
  Тож **у бета-версії потрібно один раз увійти в Google заново**.
- Основну програму й бету можна мати одночасно, але **не запускайте обидві на одні й ті самі пари**
  (обидві зайдуть у Meet). Для тесту вимкніть автозапуск старої: `python3 auto_meet.py --autostart-off`.

## Збірка (GitHub Actions)
Workflow `build-beta` запускається при пуші в гілку `beta` (зміни в `beta/`) або вручну
(Actions → build-beta → Run workflow, гілка `beta`). Артефакти:
`AutoMeetBeta-macos` (.dmg, Intel + Apple Silicon) і `AutoMeetBeta-windows` (.exe установник).

### Підпис і нотаризація Apple (Secrets репозиторію)
Без секретів macOS-збірка робиться без підпису (як зараз). Щоб Gatekeeper не лякав:

| Secret | Що це |
|---|---|
| `MAC_CERT_P12_BASE64` | сертифікат **Developer ID Application**, експортований з Keychain у `.p12`, у base64 (`base64 -i cert.p12 \| pbcopy`) |
| `MAC_CERT_PASSWORD` | пароль, який ви задали при експорті `.p12` |
| `APPLE_ID` | ваш Apple ID (e-mail) |
| `APPLE_APP_SPECIFIC_PASSWORD` | пароль програми з appleid.apple.com → Sign-In and Security → App-Specific Passwords |
| `APPLE_TEAM_ID` | Team ID з developer.apple.com → Membership |

Для Windows підпису поки немає: SmartScreen покаже «Windows захистила ваш ПК» → «Докладніше» → «Все одно виконати».

## Релізи та оновлення програми

**Де лежить найсвіжіша версія.** У GitHub Releases репозиторію. Кожен реліз містить файли з *постійними іменами*:

| Файл | Для кого |
|---|---|
| `AutoMeet-Windows.exe` | Windows (установник) |
| `AutoMeet-macOS-arm64.dmg` | Mac на Apple Silicon (M1/M2/M3/M4) |
| `AutoMeet-macOS-intel.dmg` | Mac з процесором Intel |

Постійне посилання на актуальну **стабільну** версію (можна давати студентам і викладачам):
`https://github.com/repaulshadow/automeet/releases/latest/download/AutoMeet-Windows.exe`
(для Mac замініть ім'я файлу). Поки всі версії позначені як `beta` (пре-реліз), «latest» їх не показує:
давайте посилання на сторінку `https://github.com/repaulshadow/automeet/releases`.

**Як випустити нову версію.** Два способи, результат однаковий:
1. На GitHub: Releases → Draft a new release → у «Choose a tag» впишіть `v0.2.0-beta.1` (Create new tag, target `beta`),
   позначте «Set as a pre-release» для бети → Publish. Workflow сам збере інсталятори й прикріпить їх до цього релізу.
2. Командою: `git tag v0.2.0-beta.1 && git push origin v0.2.0-beta.1` (з гілки `beta`).

Номер версії програми береться з тегу (`v0.2.0-beta.1` → `0.2.0-beta.1`). Стабільний реліз: тег без суфікса, наприклад `v1.0.0`.

**Як програма дізнається про оновлення.** Раз на 12 годин (і за кнопкою Налаштування → «Перевірити оновлення програми»)
вона питає GitHub API про найновіший реліз. Користувачі беті бачать і пре-релізи, користувачі стабільної версії лише стабільні.
Якщо є новіша версія, програма показує вікно: **Завантажити** (відкриває потрібний файл для вашої системи), **Нагадати пізніше**
або **Пропустити цю версію**. Після завантаження треба вийти з програми (трей → Вийти) і запустити інсталятор.
Розклад оновлюється окремо й автоматично, перевипускати програму через зміну розкладу **не треба**.

**Для іншого навчального закладу.** Усі адреси зібрані в `beta/src/config.js` (`REPO`, `SCHEDULE_BRANCH`): форкніть репозиторій,
змініть `REPO`, покладіть свій `schedule.json` у корінь і випускайте релізи там.

## Локальний запуск (для розробки)
```
cd beta
npm install
npm start          # вікно програми
npm test           # тести логіки (порівняння з Python)
```
Перевірки з віртуальним екраном: `xvfb-run -a node test/ui-smoke.js` (інтерфейс),
`xvfb-run -a node test/engine-smoke.js` (вхід на макетну «пару»).
Зміна папки даних для тестів: змінна `AUTOMEET_DATA_DIR`.

## Структура
- `src/logic.js` — розклад, суботи, пошук викладача, порівняння предметів (портовано з Python, є тести).
- `src/engine.js` — браузер Playwright, вхід на пари, Classroom, планувальник, заміни.
- `src/store.js` — стан, журнал, оновлення розкладу з GitHub.
- `src/main.js` — вікно, трей, автозапуск, сценарії налаштування.
- `renderer/` — інтерфейс.

## Переведення з бети в основну версію
Коли бета перевірена: змерджити гілку `beta` у `main` (папка `beta/` нічого не ламає),
і лише потім вирішувати, чи прибирати Python-версію.
